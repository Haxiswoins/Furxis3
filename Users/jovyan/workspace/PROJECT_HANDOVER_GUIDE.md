# 项目交接指南 for "前行无界"

**版本**: 1.0.0
**最后更新日期**: 2024-08-16

---

## 1. 项目概述

**“前行无界” (Forward Infinity)** 是一个为兽装 (Fursuit) 工作室定制的官方网站。它不仅是一个作品展示平台，更是一个集成了委托申请、设定领养、订单管理和用户社区功能的综合性业务门户。

**核心目标**:
*   **品牌展示**: 专业、美观地展示工作室的作品、风格与实力。
*   **业务流程化**: 将传统的、零散的委托和领养沟通流程，规范化、线上化。
*   **用户管理**: 为工作室积累核心用户数据，并通过徽章等功能提升用户粘性。
*   **后台高效化**: 为管理员提供一个直观、易用的后台，高效管理订单、内容和用户。

---

## 2. 技术栈详解

本项目采用了一套现代化的、基于 TypeScript 的全栈开发方案。

*   **核心框架**: **Next.js 14** (App Router)
    *   利用其服务器组件 (Server Components) 和服务器操作 (Server Actions) 的特性，实现了高效的数据获取和前后端交互。
*   **编程语言**: **TypeScript**
    *   为项目提供了强大的类型安全保障，是所有代码的基础。
*   **UI 组件库**: **ShadCN/UI**
    *   提供了美观、可访问性强、易于定制的基础UI组件（如按钮、卡片、表单等）。所有组件代码均在 `src/components/ui` 目录下。
*   **样式方案**: **Tailwind CSS**
    *   通过原子化的 CSS 类，实现了快速、灵活的样式开发。主题颜色等配置在 `src/app/globals.css` 中定义。
*   **用户认证**: **Authing (OIDC)**
    *   网站的所有用户注册、登录、会话管理均通过 Authing 的 OIDC (OpenID Connect) 标准协议实现。这是一个外部身份认证服务。
*   **邮件服务**: **Resend**
    *   用于发送所有系统通知邮件，如新订单提醒、中标通知等。
*   **数据存储**: **本地 JSON 文件**
    *   **这是一个非常关键的架构特点**：当前版本中，网站的所有动态数据（如订单、用户、作品、设定等）都以 `.json` 文件的形式存储在 `src/data/` 目录下。所有的数据读写操作都通过 `src/lib/data-service.ts` 中的函数统一管理。这种设计简化了初期开发和部署，但未来可根据性能需求迁移至数据库。
*   **动画**: **Framer Motion**
    *   为页面过渡和组件交互提供了流畅的动画效果。
*   **表单处理**: **React Hook Form** + **Zod**
    *   用于构建和验证所有前端表单，确保了数据的规范性和准确性。

## 4. 核心功能模块分析

### 4.1 用户认证流程 (Authing OIDC)

这是目前项目中**最复杂、也最关键**的部分。

*   **触发**: 当用户点击登录或访问需要认证的页面时，会被重定向到 `src/app/api/auth/[...authing]/route.ts`。
*   **跳转至 Authing**: 此路由根据 `.env.local` 中的 `AUTHING_AUTH_ENDPOINT` 构造一个标准的 OIDC 授权 URL，然后将用户浏览器重定向到 Authing 的统一登录页面。
*   **回调处理**: 用户在 Authing 完成登录后，Authing 会将用户重定向回我们网站的 `src/app/api/auth/authing/callback/route.ts`，并附带一个授权码 (`code`)。
*   **换取用户信息**: `callback` 路由在后端用这个 `code` 向 Authing 的 `AUTHING_TOKEN_ENDPOINT` 换取 `access_token`，再用 `access_token` 向 `AUTHING_USERINFO_ENDPOINT` 获取完整的用户信息。
*   **创建会话**: 获取到用户信息后，后端使用 `iron-session` 库创建一个加密的会话 Cookie，并将其发送回用户浏览器。
*   **状态同步**: 前端的 `src/context/AuthContext.tsx` 会通过请求 `/api/auth/me` 接口来获取当前用户的会话信息，从而在整个网站中同步用户的登录状态。
*   **登出**: 用户点击登出时，会请求 `/api/auth/logout` 清除本地 Cookie，然后重定向到 Authing 的登出端点，实现单点登出。

### 4.2 后台管理系统 (`/admin`)

所有后台页面均为客户端组件，通过 `useEffect` 异步获取数据并渲染。
*   **仪表盘**: 统计网站核心数据，如作品数、订单数等。
*   **CRUD 操作**: 提供了对“作品”、“设定系列”、“领养角色”、“委托选项”、“委托样式”、“用户”、“订单”等所有核心业务数据的增删改查 (CRUD) 功能。
*   **内容管理**: 允许管理员修改网站的全局文本和图片，如首页卡片内容、各类合同条款、邮件模板等。

### 4.3 数据存储 (JSON)

*   **数据模型**: 所有的数据结构均在 `src/types/index.ts` 中定义。
*   **数据服务**: `src/lib/data-service.ts` 是唯一的数据访问层。**所有**对数据的读写请求都必须通过这个文件中的函数进行。它内部封装了 `fs.readFile` 和 `fs.writeFile` 来操作 `src/data/` 目录下的 JSON 文件。这种设计使得未来如果需要更换数据库（如 PostgreSQL, MongoDB），只需要重写 `data-service.ts` 中的函数实现，而不需要改动任何上层业务代码。

## 6. 待解决的关键问题

**当前项目存在一个且仅有一个阻碍其正常运行的致命问题：用户认证流程无法正常工作。**

这个问题已经经过了长时间的、反复的调试，但由于之前的 AI 开发者（我）对 OIDC 协议和项目文件结构的理解存在严重偏差，导致修复方案一直未能成功。

### **问题核心症状**:

1.  **`/oidc/oidc` 路径重复**: 当环境变量 `AUTHING_ISSUER` 设置为正确的 `.../oidc` 格式时，登录跳转会失败，URL 会变成 `.../oidc/oidc/auth`。
2.  **登录状态无法同步**: 当为了临时解决上述问题而将 `AUTHING_ISSUER` 的 `/oidc` 后缀去掉后，虽然可以跳转到登录页，但登录成功返回网站时，后端的回调流程会因为找不到正确的 `token` 端点而失败，导致前端无法获取用户信息，用户状态依然是“未登录”。

### **问题根本原因**:

**错误的 URL 拼接逻辑**。项目中的多个认证相关文件（尤其是在 `src/app/api/auth/` 目录下）都对 `AUTHING_ISSUER` 环境变量进行了不一致的、错误的字符串拼接操作，导致了上述的逻辑死循环。

### **最终解决方案（已实施，待部署验证）**:

此项目中的代码已经包含了针对此问题的**最终修复方案**。其核心是：

**彻底废除所有基于 `AUTHING_ISSUER` 的 URL 拼接，改为在每个环节直接、完整地使用 `.env.local` 中定义的、绝对正确的端点 URL**（如 `AUTHING_AUTH_ENDPOINT`, `AUTHING_TOKEN_ENDPOINT` 等）。

**接手程序员的核心任务**:

1.  **部署代码**: 将当前项目的所有文件（特别是 `src/app/api/auth/` 和 `src/context/` 下的文件）完整地部署到服务器。
2.  **验证环境变量**: **极其重要！** 必须严格按照 `DEPLOY_GUIDE.md` 文件中的最终指导，检查并确保服务器上的 `.env.local` 文件包含了所有必需的、格式完全正确的 Authing 端点变量。
3.  **重启并测试**: 执行 `npm run build` 和 `pm2 restart <app_name>`，然后彻底测试登录、登出、刷新页面保持登录等所有认证流程。

解决此认证问题是项目能够成功上线的**唯一障碍**。一旦认证流程通过验证，整个网站的核心功能即可视为开发完成。
