
# Git 与 GitHub 工作流程指南 for Firebase Studio

本文档将指导您如何将这个“前行无界”项目与您自己的 Git 和 GitHub 仓库连接起来，实现代码的版本控制、备份和恢复。

---

### **前提条件**

1.  **已安装 Git**: 您已经在您的电脑上成功安装了 Git。
2.  **拥有 GitHub 账户**: 您需要一个 GitHub 账户。
3.  **代码编辑器**: 推荐使用 VS Code，因为它内置了强大的 Git 功能。

---

### **第 1 步：创建您的 GitHub 仓库**

1.  登录您的 GitHub 账户。
2.  点击右上角的 "+" 号，选择 "New repository"。
3.  为您的仓库取一个名字（例如 `forward-infinity-project`）。
4.  **非常重要**：请**不要**勾选 "Add a README file", "Add .gitignore", 或 "Choose a license"。我们要从一个完全空的仓库开始。
5.  点击 "Create repository"。
6.  创建成功后，您会看到一个页面，上面显示了您的仓库地址，格式通常是 `https://github.com/YourUsername/YourRepositoryName.git`。**请复制这个地址**，下一步会用到。

---

### **第 2 步：将项目与您的 GitHub 仓库关联**

现在，我们要将您在 Firebase Studio 中的项目代码与您刚刚创建的 GitHub 仓库连接起来。

1.  在 Firebase Studio 中，打开终端（或用您自己的终端/代码编辑器打开这个项目所在的文件夹）。
2.  运行设置脚本 `SETUP_GIT.sh`。这个脚本会帮您完成所有初始化的复杂工作。

    您需要像这样运行它，把您刚才复制的仓库地址作为参数传进去：

    ```bash
    sh ./SETUP_GIT.sh "https://github.com/YourUsername/YourRepositoryName.git"
    ```
    > **注意**: 请确保将上面的地址替换为您自己的真实仓库地址，并用引号包裹起来。

3.  脚本会自动完成以下操作：
    *   清理旧的（可能存在的）Git 配置。
    *   初始化一个新的本地 Git 仓库。
    *   将您的项目与您的远程 GitHub 仓库关联起来。
    *   将所有项目文件添加到暂存区，并创建第一次“初始提交”。

4.  脚本执行完毕后，会提示您运行最后一步命令，将您的代码首次推送到 GitHub：

    ```bash
    git push -u origin main
    ```
    在终端中输入这个命令并回车。现在，刷新您的 GitHub 仓库页面，您会发现所有的项目文件都已经上传上去了！

---

### **第 3 步：日常开发与同步 (本地)**

当您在 Firebase Studio 中开发，并准备好将一批修改“存档”并推送到 GitHub 时，请遵循以下流程。

1.  **进行修改**: 您在 Firebase Studio 中提出需求，我为您修改代码。
2.  **运行同步脚本**: 当您准备好保存一个版本时，请在终端运行同步脚本 `SYNC_TO_GIT.sh`。

    您可以直接运行（脚本会提示您输入描述）：
    ```bash
    sh ./SYNC_TO_GIT.sh
    ```
    或者，您可以直接把描述信息作为参数：
    ```bash
    sh ./SYNC_TO_GIT.sh "增加了首页背景图功能"
    ```

3.  **推送至 GitHub**: 脚本完成后，会提示您运行 `git push` 命令。
    ```bash
    git push
    ```
    运行此命令后，您的最新修改就安全地同步到 GitHub 上了。

---

### **第 4 步 (最重要)：在服务器上更新网站**

当您在第 3 步中将新代码推送到 GitHub 后，您服务器上运行的网站**不会自动更新**。您必须登录到服务器，按照以下**完整、严格的四步流程**来部署最新版本。

#### **场景一：常规更新 (推荐)**

这是最常用、最安全的更新方式。它会**强制用 GitHub 上的代码覆盖服务器上的任何本地修改**，确保部署的代码和您在 GitHub 上看到的一模一样。

1.  **登录服务器**: 通过 SSH 登录到您的腾讯云服务器。
    ```bash
    ssh root@175.178.237.158
    ```

2.  **进入项目目录**:
    ```bash
    cd /root/forward-infinity
    ```

3.  **开始标准更新流程 (四步缺一不可)**:

    **第一步: 获取并强制重置代码**
    这个流程会先从 GitHub 获取最新的代码信息，然后用 `git reset --hard` 命令**强制覆盖**本地所有文件，使其与 GitHub 上的 `main` 分支完全一致。
    ```bash
    # 从远程仓库获取所有分支的最新信息
    git fetch origin

    # 强制将本地分支重置为与远程 main 分支完全一致的状态
    # 如果您想从 3.2 分支更新，就把 "main" 换成 "3.2"
    git reset --hard origin/main
    ```

    **第二步: 安装/更新依赖包 (关键！)**
    这是一个好习惯，即使您认为没有添加新库，也请运行它，以防万一。
    ```bash
    npm install
    ```

    **第三步: 重新构建应用 (最关键的一步！)**
    这个命令会把您所有最新的代码编译和打包成服务器可以直接运行的最终文件。**跳过此步，您的网站将永远运行旧代码。**
    ```bash
    npm run build
    ```

    **第四步: 重启服务**
    这个命令会告诉进程管理器 PM2：“用刚刚构建好的新文件，重新启动网站。”
    ```bash
    pm2 restart 前行无界
    ```

#### **场景二：尝试合并服务器上的修改 (不推荐)**

如果您**确实**在服务器上做了一些**希望保留**的临时修改，并想尝试将它们与 GitHub 上的代码合并，您可以使用 `git pull`。但这有可能会产生冲突。

```bash
# 进入项目目录后...

# 尝试拉取并合并 main 分支的更改
git pull origin main

# 如果没有冲突，继续执行构建和重启步骤
npm install
npm run build
pm2 restart 前行无界
```

> **强烈建议**: 服务器应始终被当作一个纯粹的部署环境。**请尽量避免在服务器上直接修改代码**，所有的代码修改都应该在您的开发环境（如 Firebase Studio）中完成，然后推送到 GitHub，最后再通过**场景一**的流程部署到服务器。

---

### **第 5 步：从 GitHub 合并其他来源的更改 (本地开发)**

当您在其他地方（如您自己的电脑或 GitHub 网站上）对代码进行了修改，并希望将这些更改同步到 Firebase Studio 时，就需要从 GitHub `pull` (拉取) 代码。

1.  **首先，保存您在 Studio 中的本地更改！**
    ```bash
    sh ./SYNC_TO_GIT.sh "在从 GitHub 拉取前，保存我的本地修改"
    ```
    > **重要**: 运行此脚本后，**请暂时不要 `push`**。

2.  **从 GitHub 主分支拉取并合并**
    ```bash
    git pull origin main
    ```

3.  **处理合并冲突 (如果发生)**
    如果 Git 提示存在 `CONFLICT`，您需要手动解决这些冲突，然后再次运行 `sh ./SYNC_TO_GIT.sh "解决合并冲突"` 来创建一个新的提交。

4.  **推送最终版本**
    当所有代码都已成功合并，运行 `git push` 将最终版本同步回 GitHub。

---

通过遵循以上流程，您就可以完全掌控您的项目版本了！
